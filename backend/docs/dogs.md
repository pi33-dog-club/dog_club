# Собаки

Реализованы регистрация и карточки собак, владельцы, родословные, учёт уже
присвоенных титулов, поиск и история. Основания: ТЗ §4.3 (страница PDF 14),
поля учётной карточки (PDF 8), физическая схема второго PDF и актуальные правила
третьего PDF (идентификация, родословные, постоянные титулы).
История изменений физической модели описана в [аудите схемы](database-audit.md).

## Доступ

| Активный профиль | Чтение | Изменения |
| --- | --- | --- |
| staff | Все собаки и история | Регистрация, карточки, владельцы, родословные, записи титулов |
| leader | Все собаки и история | Недоступны |
| owner | Только текущие собственные собаки при активном членстве | Недоступны |
| admin, veterinarian, expert | Общий каталог недоступен | Предметные профессиональные сценарии — отдельно |

Права нескольких профилей не объединяются. Неактивное членство закрывает весь
раздел owner, включая список, карточку, историю и справочники собак. Состояние
членства, аккаунта, сессии и профиля проверяется в БД на каждом запросе;
истечения JWT ждать не нужно. Управление своей сессией и переключение на другой
включённый профиль сохраняются. Полная блокировка аккаунта отзывает все сессии.

Собака имеет от одного до 100 различных владельцев — существующих карточек
членов клуба. Карточка владельца может не иметь аккаунта или иметь неактивное
членство: запись о собственности сама по себе не предоставляет вход и полномочия.
После передачи собаки прежний владелец немедленно теряет чтение карточки и
истории. Текущий владелец видит историю этой собаки, включая прежние связи.
Ответы dogs содержат ID владельцев, без ФИО, контактов и адресов; чтение людей
подчиняется отдельным правилам [members](members.md).

Чужая собака или её история для owner возвращает 404. Отсутствие своей карточки,
неактивное членство или неподходящий профиль — 403. Список owner принудительно
ограничен его ID; запрос фильтра owner_id другого человека запрещён.

## Карточка и идентификация

Регистрация требует кличку, дату рождения, тип и непустой уникальный номер
идентификатора, статус, породу, окрас, пол и владельцев. Черновиков без
идентификатора нет. Кличка и номер ограничены 100 Unicode-символами, краевые
пробелы убираются, управляющие символы запрещены. Номер хранится строкой:
ведущие нули сохраняются. Уникальность глобальна для всех типов, регистр
учитывается. Формат конкретного микрочипа или клейма автоматически не угадывается.

Даты — YYYY-MM-DD, не позднее текущей даты UTC. Необязательная дата идентификации
не может предшествовать рождению. ID справочников должны существовать;
справочники доступны только для чтения через GET /dog-dictionaries.

Статусы содержат is_active. Активен только «На учёте»; «Снята с учёта», «Умерла»,
«Потеряна» и «Исключена» запрещают новые и исправленные осмотры, вакцинации,
занятия, вязки и допуск к мероприятиям (лаб. 3, fn_dog_active_check). Статус
меняется обычным PATCH, история карточки хранит смену; правило смотрит только на
текущий статус, поэтому найденная собака снова доступна после возврата «На учёте».

Дата рождения — не ранее 1900-01-01.

Рост height_cm (0.01–150 см) и вес weight_kg (0.01–200 кг) необязательны;
максимум два знака после точки. В БД numeric(7,2); лишние знаки
API отклоняет, не округляя молча. Это текущие значения, не журнал измерений.
PATCH сохраняет пропущенные поля; null очищает только рост и вес. Идентификатор
при PATCH заменяется целиком; его date может быть null.

## Родословная и внешние родители

У собаки максимум одна родословная. Её number и issuer — номер документа и
выдавшая организация, отдельно от идентификатора животного. Заполненные оба поля
считаются родословной, известной на три поколения (лаб. 3): этого достаточно для
допуска на выставки и соревнования без карточек всех предков. Глобальная
уникальность номера документа не вводится. Для каждого родителя допускается
ссылка на существующую собаку, внешнее описание либо null (неизвестен).

Пример PUT /dogs/{dogID}/pedigree, где мать зарегистрирована, отец внешний:

```json
{
  "version": 1,
  "number": "РКФ 1234567",
  "issuer": "РКФ",
  "mother": {"dog_id": 12},
  "father": {
    "external": {
      "nickname": "Барон",
      "pedigree_number": "РКФ 7654321",
      "issuer": "РКФ"
    }
  }
}
```

Внешние сведения хранятся прямо в родословной потомка. Они не создают карточку
собаки, владельца или общий каталог внешних животных. Обязательна хотя бы кличка
или номер родословной; организация без них недостаточна. Номер/кличка — до 100,
организация — до 150 символов. Совпадение текста не означает тождество собак.

Если отца позже зарегистрируют, сотрудник проверит документы и явно заменит
father на `{"dog_id":34}`, передав текущую version и остальные поля родословной.
Автоматического связывания по имени или номеру нет. Старое описание остаётся
в снимках истории. PUT заменяет родословную целиком; пропущенные необязательные
поля очищаются. Чтобы убрать родителя, передайте null.

Для существующих родителей проверяются пол («Сука»/«Кобель»), рождение раньше
потомка, отсутствие самоссылки, одинакового родителя и циклов любого размера.
Изменение пола или даты рождения родителя перепроверяет его зарегистрированных
потомков. Для внешнего описания проверить пол, возраст и цепочку предков нельзя.
Одинаковая порода и минимальный возраст вязки здесь не навязываются; допуск
к разведению относится к будущему модулю.

В ответе связанный родитель содержит краткие сведения об этой собаке, без
владельцев и их персональных данных; предки рекурсивно не раскрываются.
Эти сведения читаются актуальными: изменение клички родителя не увеличивает
версию потомка. История хранит снимки на момент изменения карточки потомка.

## Титулы

API записывает уже присвоенные официальные титулы из справочника; автоматически
не присваивает их по достижениям, не рассчитывает срок и не снимает по времени.
Один вид титула можно записать собаке один раз. Дата присвоения необязательна,
но при указании не раньше рождения и не в будущем; basis — основание до 1000
символов. Изменение даты рождения не может сделать дату титула недопустимой.

Исправление реквизитов через PUT и удаление ошибочной записи через DELETE
требуют reason длиной 1–500 символов и текущую version. DELETE содержит JSON
тело, например `{"version":4,"reason":"Титул ошибочно указан другой собаке"}`.
Это исправление учёта с сохранением снимков и причины, не лишение официального
титула. Нет физического удаления собаки или API изменения истории.

## Фото

У собаки одно текущее фото: JPEG или PNG до 5 МиБ и 40 мегапикселей. Тип
проверяется по содержимому, а не по имени и заявленному типу. Байты лежат в том
же закрытом хранилище, что и файлы документов (DOCUMENTS_DIR), строка `dog_photo`
даёт к ним доступ. Загружает, заменяет и убирает фото только staff; видят его
staff, leader, ветеринар и эксперт, владелец — только у своих текущих собак.

У фото своя version: замена фото не меняет version карточки собаки. Так новое
фото не делает неактуальными подтверждения квалификации на мероприятиях и не
помечает документы как «источник изменился». Первая загрузка передаёт version=0,
замена — текущую версию фото; версия растёт и после удаления, поэтому устаревший
клиент не заденет новое фото. Убрать фото можно с текущей версией и причиной.
Загрузка и удаление пишутся в историю собаки (`photo_set`, `photo_removed`).
Байты пишутся до транзакции и удаляются, если она не прошла; прежний файл
удаляется после замены или удаления.

## Маршруты и HTTP-контракт

Префикс всех путей — `/api/v1`, требуется Bearer access JWT. Схемы и примеры
полей — в [OpenAPI](../api/openapi.yaml). JSON ограничен 16 КиБ; неизвестные
поля, включая вложенные, отклоняются. Ошибки используют RFC 9457.

| Метод и путь | Результат |
| --- | --- |
| GET /dogs | dogs (краткие карточки) и next_after, 200 |
| POST /dogs | Полная карточка, 201 и Location |
| GET /dogs/{dogID} | Полная карточка с владельцами, родословной и титулами, 200 |
| PATCH /dogs/{dogID} | Изменённая полная карточка, 200 |
| GET /dogs/{dogID}/history | changes и next_after, 200 |
| PUT /dogs/{dogID}/owners | Полная замена списка владельцев; карточка, 200 |
| PUT /dogs/{dogID}/pedigree | Полная замена родословной; карточка, 200 |
| POST /dogs/{dogID}/titles | Добавление записи титула; карточка, 200 |
| PUT /dogs/{dogID}/titles/{titleID} | Исправление реквизитов с причиной; карточка, 200 |
| DELETE /dogs/{dogID}/titles/{titleID} | Исправление ошибочной записи с причиной; карточка, 200 |
| GET /dogs/{dogID}/photo | Сведения о фото (тип, размер, версия), 200; 404, если фото нет |
| GET /dogs/{dogID}/photo/file | Изображение для показа, 200 |
| PUT /dogs/{dogID}/photo | multipart: file и version; сведения о фото, 200 |
| DELETE /dogs/{dogID}/photo | JSON version и reason; 204 |
| GET /dog-dictionaries | Статусы, породы, окрасы, пол, типы идентификатора, титулы, 200 |

GET /dogs принимает q (до 100 символов), breed_id, status_id, sex_id, owner_id,
after, limit. sex_id сужает выбор матери или отца при заполнении родословной.
Поиск q — по подстроке клички, идентификатора или номера родословной, без учёта
регистра. %, _ и обратная косая черта — буквальные символы. Для поиска
по человеку staff сначала получает ID через /members и использует owner_id.
Порядок — возрастающий ID, after — последний ID прошлой страницы. limit 1–100,
по умолчанию 50; next_after=null означает конец. История использует те же правила,
но after обозначает ID записи истории. Повтор параметра отклоняется.

## Версии, транзакции и миграция

Созданная карточка имеет version=1. Каждая мутация карточки, списка владельцев,
родословной или титула требует последнюю version и увеличивает её на один.
Устаревшая версия, занятый идентификатор или повторный титул дают
409 dog_conflict; нужно перечитать карточку. Неверные поля и ссылки — 422,
недоступность хранилища — 503 dogs_unavailable без SQL и деталей соединения.

dog_changes атомарно сохраняет снимки до/после, действие, причину, ID аккаунта
и активного профиля исполнителя, роль, request_id и время. При создании before=null.
Отказ сохранения истории откатывает операцию и версию. История не попадает
в технические логи; срок её хранения требует решения перед эксплуатацией.

dogs вызывает публичные auth.Service.WithAccess и members.Service для проверки
членства и ссылок на людей. Проверки выполняются в той же транзакции, без
чужих приватных репозиториев и вложенных транзакций. Общая с auth/members
advisory lock сериализует также чтения. Это ограничение производительности
текущего варианта; внешнее I/O под блокировкой не выполняется.

Миграция 00005 добавляет обязательность непустого идентификатора, рост/вес,
version, необязательные FK родителей, внешние поля и уникальность родословной
по собаке, реквизиты титулов и dog_changes. Старые неверные данные не заменяются
выдуманными: NULL-идентификатор, отсутствующий родитель или две родословные
останавливают Up транзакционно. Down допускается только при пустом каталоге
собак, поскольку старая модель не сохранит новые сведения. Детали — в
[аудите](database-audit.md).

## Проверка

Запуск и создание администратора описаны в [README](../../README.md), назначение
staff и owner — в [auth.md](auth.md) и [members.md](members.md). Под профилем staff
получите справочники собак и создайте карточку владельца. Пример POST /dogs
(все числовые ID замените существующими из своих справочников и карточек):

```json
{
  "nickname": "Альма",
  "date_of_birth": "2023-05-10",
  "identifier": {"type_id": 1, "number": "000000000000123"},
  "status_id": 1,
  "breed_id": 1,
  "coat_color_id": 1,
  "sex_id": 2,
  "height_cm": 55.5,
  "weight_kg": 24.25,
  "owner_ids": [1]
}
```

Проверьте 201, version=1 и сохранённые ведущие нули. Повтор номера должен дать
409, отсутствие номера — 422. Укажите внешнего родителя, перечитайте карточку
и историю; отдельная карточка родителя не должна появиться. Проверьте поиск,
добавление/исправление титула с причиной, конфликт старой версии. Под owner
доступна только собственная собака. После смены владельцев прежний owner
получит 404; после прекращения членства — 403 во всём разделе, сохранив
возможность переключить другой профиль.

```bash
gofmt -l cmd internal migrations api
go test -race -count=1 ./...
export DOGCLUB_TEST_DATABASE_URL="$DATABASE_URL"
go test -race -count=1 -tags=integration ./...
go vet -tags=integration ./...
go build -o bin/ ./cmd/...
go mod verify
git diff --check
```

Все тесты, включая PostgreSQL 18.6, прошли. Проверены матрица доступа,
несколько владельцев, передача, немедленное закрытие owner-доступа, поисковые
страницы, уникальность идентификатора, измерения, родители и циклы, изменение
родителей, внешнее описание и явное связывание, титулы/причины, конкурентные
версии и полный откат при отказе истории. Миграционные тесты проверяют
сохранность старых данных и полный Up/Down на пустой одноразовой БД.

Настоящие migrate/admin/API отдельно проверены с Mailpit: приглашения, dog API,
смена профиля тем же аккаунтом, CSRF, безопасные логи, readiness и SIGTERM=0.
Одноразовая БД удалена. Рабочие люди, аккаунты и собаки тестами не создавались.

Пятая миграция применена к рабочей локальной БД: 43 таблицы с Goose, 56 FK,
собак/людей/аккаунтов нет. Настоящий API на ней вернул readiness 200
и корректно завершился по SIGTERM с кодом 0.

Связанные модули: [ветеринария](veterinary.md), [племенная работа](breeding.md),
[мероприятия](events.md), [документы](documents.md), [дрессировка](training.md).
Автоматическое присвоение титулов, черновики и удаление собак не реализованы.

Для [ветеринарного учёта](veterinary.md) dogs предоставляет
публичные чтения в общей транзакции без раскрытия персональных данных владельцев.
В приложении подключена проверка изменения даты рождения по действующим
медицинским записям.
